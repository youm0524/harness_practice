# PRD: ApplyMate

## 한 줄 요약
ApplyMate는 채용 지원서마다 반복 입력하는 개인 이력 정보를 사용자의 브라우저에 저장해두고, 사용자가 요청한 순간 현재 페이지의 지원서 입력 폼을 안전하게 자동 채우는 Chrome Extension이다.

## 문제
취업 준비생과 이직자는 회사별 채용 페이지, 채용 플랫폼, 자체 지원 시스템을 오가며 같은 정보를 반복 입력한다. 이름, 연락처, 학력, 자격증, 프로젝트 경험처럼 변하지 않는 정보도 페이지마다 필드 이름과 순서가 달라 다시 타이핑해야 한다. 이 과정은 시간이 오래 걸리고, 오타나 누락이 생기며, 특히 여러 회사를 동시에 지원할 때 피로도가 커진다.

## 목표
- 사용자가 자신의 지원서 기본 정보를 한 번만 정리하게 한다.
- 사용자가 명시적으로 실행했을 때 현재 지원 페이지의 가능한 필드를 자동으로 채운다.
- 개인정보를 외부 서버로 보내지 않고 브라우저 로컬에 보관한다.
- 자동 채우기가 틀릴 수 있는 영역에서는 무리하게 추측하지 않고 사용자가 수정할 여지를 남긴다.

## 비목표
- 모든 채용 사이트에서 100% 정확한 자동 입력을 보장하지 않는다.
- AI/LLM으로 지원서 문항 답변을 생성하지 않는다.
- 사용자의 합격 가능성을 평가하거나 추천하지 않는다.
- 지원서를 사용자 대신 제출하지 않는다.
- 계정 기반 동기화, 팀 공유, 관리자 기능은 MVP에 포함하지 않는다.

## 사용자
- 여러 회사에 반복 지원하는 취업 준비생, 이직 준비자, 인턴 지원자
- 채용 플랫폼과 회사별 자체 지원 페이지를 오가며 동일한 정보를 반복 입력하는 사용자
- 개인정보를 외부 서버에 맡기지 않고 로컬 브라우저에 보관하고 싶은 사용자
- 자기소개서 생성보다 기본 정보 입력 시간을 줄이는 데 더 큰 불편을 느끼는 사용자

## 핵심 시나리오
1. 사용자는 확장 프로그램의 options 페이지를 열고 프로필을 입력한다.
2. 사용자는 회사 지원 페이지로 이동한다.
3. 사용자는 popup을 열고 자동 채우기 버튼을 누른다.
4. ApplyMate는 현재 페이지의 입력 필드를 읽고 저장된 프로필과 매칭한다.
5. 확신도가 충분한 필드만 채우고, 채운 개수와 스킵/미매칭 개수를 popup에 보여준다.
6. 사용자는 결과를 검토하고 필요한 부분을 직접 수정한 뒤 사이트의 일반 제출 흐름을 따른다.

## 핵심 기능
1. 사용자 프로필 관리
   - 인적사항: 이름, 생년월일, 이메일, 전화번호, 주소
   - 학력: 학교명, 전공, 학위, 입학일, 졸업일, 학점
   - 자격사항: 자격증명, 취득일, 발급처
   - 프로젝트: 프로젝트 제목, 시작일, 종료일, 역할, 주요 내용, 기술 스택
2. 현재 페이지 자동 채우기
   - Content Script가 `input`, `textarea`, `select`를 스캔한다.
   - `label`, `placeholder`, `name`, `id`, `aria-label`, 주변 텍스트를 기반으로 저장된 프로필 필드와 매칭한다.
   - 사용자가 popup에서 실행했을 때만 값을 입력한다.
   - disabled, readonly, hidden, password, file, submit, button 필드는 채우지 않는다.
3. 자동 채우기 결과 피드백
   - popup에서 채워진 필드 수, 스킵된 필드 수, 실패/미매칭 필드 수를 보여준다.
   - 대표 매칭 결과 일부를 보여주되, 너무 긴 목록으로 popup을 압도하지 않는다.
   - 실패해도 페이지를 깨뜨리지 않고 사용자가 직접 수정할 수 있게 둔다.
4. 로컬 저장
   - 프로필 데이터는 `chrome.storage.local`에 저장한다.
   - MVP에서는 외부 서버, 계정 동기화, 원격 분석을 사용하지 않는다.
5. 데이터 초기화
   - 사용자는 options 페이지에서 로컬 저장 데이터를 초기화할 수 있다.
   - 초기화는 명시적 버튼과 확인 흐름을 거쳐 수행한다.

## 데이터 범위
### 저장하는 정보
| 분류 | 필드 |
|------|------|
| 인적사항 | 이름, 생년월일, 이메일, 전화번호, 주소 |
| 학력 | 학교명, 전공, 학위, 입학일, 졸업일, 학점 |
| 자격사항 | 자격증명, 취득일, 발급처 |
| 프로젝트 | 제목, 시작일, 종료일, 역할, 주요 내용, 기술 스택 |

### 저장하지 않는 정보
- 주민등록번호 전체 번호
- 비밀번호
- 금융 정보
- 건강 정보
- 가족관계 등 지원서 기본 자동 입력에 불필요한 고위험 민감정보
- 사이트 로그인 세션, 쿠키, 토큰

## UX 요구사항
- popup의 첫 화면은 자동 채우기 실행에 집중한다.
- 프로필이 비어 있으면 자동 채우기 대신 options 페이지로 이동할 수 있게 안내한다.
- options 페이지는 사용자가 긴 정보를 편집할 수 있도록 섹션 단위로 구성한다.
- 반복 항목은 추가/삭제가 가능해야 한다.
- 저장 성공, 저장 실패, 자동 채우기 실패를 분명히 표시한다.
- 자동 채우기 버튼 클릭 전에는 현재 페이지에 아무 값도 입력하지 않는다.

## 매칭 원칙
- 명확한 alias가 있는 필드만 자동 입력한다.
- 이름/성명/name, 이메일/email, 전화번호/phone/mobile처럼 한국어와 영어 표현을 모두 지원한다.
- 불확실한 필드는 스킵한다. 틀린 자동 입력보다 채우지 않는 쪽을 선택한다.
- 같은 페이지 필드에는 하나의 값만 넣는다.
- 빈 프로필 값은 절대 입력하지 않는다.

## 성공 지표
- 테스트 fixture 기준 기본 인적사항 필드 매칭 정확도 90% 이상
- 테스트 fixture 기준 금지 필드 입력 0건
- 자동 채우기 실행 후 popup이 채움/스킵/오류 결과를 표시
- 외부 네트워크 요청 없이 프로필 생성, 저장, 자동 채우기 가능
- `npm run build`, `npm run lint`, `npm run test` 통과

## MVP 제외 사항
- AI/LLM 기반 필드 추론
- 외부 서버 저장, 로그인, 클라우드 동기화
- 이력서 PDF 파싱 또는 자동 업로드
- 지원 사이트별 전용 어댑터 대량 구현
- 사이트 제출 버튼 자동 클릭
- 자기소개서 문항 자동 생성
- Chrome Web Store 배포 자동화

## 리스크와 대응
| 리스크 | 대응 |
|--------|------|
| 사이트마다 DOM 구조와 라벨 방식이 다름 | 순수 매칭 로직 테스트 fixture를 늘리고 낮은 확신도는 스킵한다 |
| 잘못된 필드에 개인정보가 들어갈 수 있음 | alias 기반 allowlist와 금지 input 타입 필터를 둔다 |
| React 제어 컴포넌트가 값 변경을 감지하지 못함 | 값 설정 후 `input`과 `change` 이벤트를 dispatch한다 |
| 사용자가 저장 위치를 오해할 수 있음 | UI에서 로컬 저장과 외부 전송 없음 원칙을 간결히 표시한다 |
| 너무 많은 권한 요청으로 신뢰를 잃을 수 있음 | MVP 권한은 자동 채우기에 필요한 최소 권한만 사용한다 |

## 디자인
- 매일 쓰는 브라우저 도구처럼 조용하고 실용적인 UI
- 팝업은 빠른 실행과 결과 확인에 집중한다.
- 옵션 페이지는 폼 편집이 오래 걸려도 피로하지 않도록 섹션형 레이아웃을 사용한다.
- 밝은 배경, 높은 가독성, 단정한 중립색, 신뢰감을 주는 녹색 포인트를 사용한다.
